# Rust macros, unsafe and async

Contents: 1. Macros · 2. unsafe and foreign code · 3. async · 4. Embedded Rust · Sources

## 1. Macros (Rust)

- `name!(…)` and `#[attribute]` are macros: declarative (`macro_rules!`) or procedural; Rust has no reflection. [S1]
- A macro adds code that is not in the file. To see it, `cargo expand <path::to::item>` prints the expanded code when `cargo-expand` is installed; the output is a debugging aid, not the source. [S2]
- C# landmark: source generators. [S1]

## 2. unsafe and foreign code (Rust)

- `unsafe { … }` opens five operations: dereference a raw pointer, call an `unsafe` function, touch a `static mut`, implement an `unsafe` trait, read a field of a `union`; the borrow checker stays active. [S3]
- Raw pointers can ignore the borrowing rules. [S3]
- `unsafe extern "C" { … }` calls C code; `#[unsafe(no_mangle)]` exports to C. C# landmark: `DllImport`. [S3]

## 3. async (Rust)

| You read | Meaning | C# landmark |
| --- | --- | --- |
| `async fn` and `.await` | A lazy future: nothing runs before `.await`; no built-in executor, hence `#[tokio::main]`; cancelling means dropping the future [S1] | A `Task` starts at once; `await` is a prefix [S1] |
| `tokio::join!` | Wait for all [S1] | `Task.WhenAll` |
| `tokio::select!` | First to finish; the other branches are cancelled [S1] | `Task.WhenAny`, which cancels nothing |

## 4. Embedded Rust (registers and interrupts)

- Three layers: the architecture crate, the peripheral access crate generated by `svd2rust` from the vendor file, the hardware abstraction crate. [S4]
- On a register, `read()` reads, `write(…)` writes and resets the other fields to their default, `modify(…)` changes only the named fields. [S4]
- `Peripherals::take()` returns an `Option`: each peripheral has one owner only. [S4]
- An interrupt handler carries `#[interrupt]` and the interrupt name; the rest of the code cannot call it; if the cause is not cleared, the handler can be called again forever. [S5]
