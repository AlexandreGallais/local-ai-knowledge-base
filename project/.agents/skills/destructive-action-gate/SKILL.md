# Destructive action gate

**Core rule:** an action that cannot be undone needs the human's explicit yes in this conversation, given after you showed exactly what it destroys.

## Irreversible actions

| Area | Commands |
| --- | --- |
| Files | `rm -rf`, `rm` on files you did not create, `find ... -delete`, overwriting with `>` or `write` a file you did not write |
| Git | `git push --force` or `--force-with-lease`, `git reset --hard`, `git clean -f`, `git branch -D`, `git push origin --delete`, `git checkout -- <file>` on uncommitted work, `git stash drop` |
| Data | `DROP`, `TRUNCATE`, `DELETE` without `WHERE`, migrations that remove columns |
| Containers | `podman rm -f`, `podman volume rm`, `podman system prune`, `podman image prune -a` |
| Remote | deleting a GitLab branch, tag, release, pipeline or variable with `glab` or the API |

## Procedure

1. Show what will be lost: run the read-only twin (`git status`, `git diff --stat`, `ls -la <path>`, `SELECT COUNT(*)`, `podman volume inspect`).
   - Check: the output is in your reply.
2. Propose a safer path if one exists: a backup branch, a copy, `git revert`, a rename.
   - Check: the safer path is named or you state there is none.
3. Ask with the `question` tool: the exact command, what it destroys, the safer path.
   - Check: the human answered yes to this exact command.
4. Run exactly the approved command, nothing broader.
   - Check: the command run equals the command approved.

## Stop and ask the human if

- Any action of the table is needed, even when you are sure. Approval for one command does not cover the next.

## Common mistakes

| If you think... | Reality |
| --- | --- |
| "It is only a build folder." | Ask anyway, or prove it is regenerated by a command. |
| "The user approved a delete earlier." | Approval covers one command. Ask again. |
| "A permission prompt will catch it." | The rule holds even without a prompt. |

## Definition of done

- [ ] No irreversible action ran without an explicit yes for that exact command.
- [ ] What it destroyed was shown before.
