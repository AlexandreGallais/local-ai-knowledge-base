# Skill template

**Core rule:** every skill starts from `assets/SKILL.template.md` and ends with `check-skill` at `0 findings.`

## When to use

- Use when: the user asks for `/skill-template`, or to see the layout and checklist of a skill.
- Do not use when: you write a skill end to end. Use `writing-skills`, which copies this template.

## Layout

```text
.agents/
  skills/
    CORE_RULES.md          # always-loaded rules, copied into AGENTS.md
    SKILLS_INDEX.md        # generated by the skill skill-index
    _templates/            # family templates for seeds (mode D)
    _eval/                 # one test log per skill
    _licenses/             # licence texts of the adapted skills
    <name>/
      SKILL.md
      references/          # optional; SOURCE.md when adapted from another skill
      scripts/             # optional; executable, English comments
      assets/              # optional; file templates
  skills-drafts/           # unfinished skills: skeletons, BRIEF.md, SEED.md
```

## Procedure

1. Copy `assets/SKILL.template.md` of this folder to `.agents/skills/<name>/SKILL.md`, or to `.agents/skills-drafts/<name>/` while it is unfinished.
   - Check: the folder name equals the `name` field.
2. Fill every angle-bracket placeholder; delete the optional sections you do not use, keep the mandatory ones.
   - Check: no `<` placeholder is left in the file.
3. Run the checker on the folder.
   - Check: `node .agents/skills/skill-template/scripts/check-skill.ts .agents/skills/<name>` prints `0 findings.`; without Node, `python3 .agents/skills/skill-template/scripts/check_skill.py .agents/skills/<name>` prints the same.
4. Go through the validation checklist below.
   - Check: every box can be ticked with evidence.

## Validation checklist

- [ ] `name` equals the folder; lowercase letters, digits, hyphens; 64 characters at most.
- [ ] `description` in double quotes, third person, with `Use when` and real triggers; at most 1,024 characters. A manual skill starts with `Manual: run only when the user explicitly asks for /<name>.`
- [ ] `metadata`: catalogue `id`, `stars`, `nature`, `mode`, `wave`, `load`.
- [ ] The `**Core rule:**` line is in the first 10 lines of the body.
- [ ] Every numbered step of `## Procedure` has its `- Check:` line.
- [ ] Sections present: `Stop and ask the human if`, `Common mistakes`, `Definition of done`.
- [ ] Guardrail at most 60 lines; any skill at most 500 lines.
- [ ] Every file of `references/` is cited in `SKILL.md`; `references/SOURCE.md` exists for an adapted skill.
- [ ] No `FILL` marker, no `BRIEF.md` or `SEED.md` left in a finished skill; no secret, no internal value.
- [ ] Test logged in `_eval/<name>.md`; `SKILLS_INDEX.md` regenerated.

## Stop and ask the human if

- The skill needs an internal value (host, mirror, path) and its file may leave the internal environment.

## Common mistakes

| If you think... | Reality |
| --- | --- |
| "I can skip the checker for a small edit." | One unquoted colon breaks the header. Run it. |
| "References can link to more references." | One level deep only. |

## Definition of done

- [ ] The new skill was copied from `assets/SKILL.template.md`.
- [ ] `check-skill` prints `0 findings.`
- [ ] Every box of the validation checklist is ticked.

## References

- `assets/SKILL.template.md`: the template to copy.
- `scripts/check-skill.ts` and `scripts/check_skill.py`: the checker, in Node and in Python, same output.
