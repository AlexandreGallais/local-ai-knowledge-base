# OpenAPI code generation

**Core rule:** generated code is regenerated from the schema with one command and never edited by hand.

## Procedure

1. Find the schema and the generator the project uses (scripts in `package.json`, Makefile, build plugin).
   - Check: the generation command is known.
2. Run the generation.
   - Check: generated files change only where the schema changed (`git diff --stat`).
3. Build and run the tests that use the client.
   - Check: green, or the breaking changes are listed.
4. Commit schema and generated code together, or regenerate in the build, as the project does.
   - Check: no hand edit in generated files (`git diff` shows only generator output).

## Stop and ask the human if

- The schema must be fetched from a service you cannot reach.

## Common mistakes

| If you think... | Reality |
| --- | --- |
| "Patch the generated file." | The next generation erases it. Fix the schema or the generator config. |
| "Write the types by hand, it is faster." | They drift from the API at the first change. |

## Definition of done

- [ ] Code regenerated by command; tests green; no hand edit in generated files.
